# 发布检查清单

> 复制这份到 issue 或 PR 里逐项勾选。**带 ⚠️ 的是安全底线，不满足就不要发布。**
>
> 背景：DSH 对客户端插件的容错设计是"全有或全无"——一个 bundle 抛错，
> 应用**直接拒绝启动**；而应用的恢复模式会**重写用户的 `package.json` 与 `cordis.patch.yml`**，
> 抹掉他手写的 provider 配置。所以"发布一个可能让人开不了应用的东西"代价极不对称。

---

## 一、安全底线

- [ ] ⚠️ **客户端 bundle 顶层不抛异常。** 所有初始化包在 try/catch 里；
      `apply()` 内部失败只降级（不注册/不渲染），不向上抛
- [ ] ⚠️ **验证过失败时的行为**：故意在 `apply()` 里抛错，确认应用仍能启动（或至少不致命）
- [ ] ⚠️ **`cordis.patch.yml` 只追加、不覆盖。** 用 `insert` 而不是替换整行
- [ ] ⚠️ **卸载路径可用**：删软链/依赖 + 删插件行 + 重启，应用能正常启动
- [ ] ⚠️ **读出过 `package.json` 与 patch 的备份策略**，README 里写明怎么回滚
- [ ] ⚠️ **没有在用户不知情时改写别人的配置**（我做错过：恢复模式清空后我重建时差点丢掉用户的 Ollama 行）

## 二、产物正确性

- [ ] 产物以 `window.__ModuleLoader__.load({` 开头（**双下划线**）
- [ ] 产物里**没有**裸 `_ModuleLoader__`（单下划线 = 未声明标识符）
- [ ] 顶层**同步**注册，无 `setInterval` 轮询、无延迟注册
- [ ] 导出 **`apply`** 和 `inject`（不是 `install`）
- [ ] 默认导入绑定整个模块对象（`require("react")` 而非 `require("react").React`）
- [ ] 安装前有硬闸门脚本，且**反向验证过**（故意改坏能拦下）
- [ ] 闸门覆盖到**渲染层**：真正构造一次组件，不能只验证注册

## 三、安装路径

- [ ] 测过 `dsh plugin --profile <p> add <pkg>` 标准路径（**别只测自己的脚本**）
- [ ] 测过从零开始的全新 profile 安装（不是在被改过多次的环境里测）
- [ ] README 写明**必须重启应用**（刷新页面不够——启动图是启动时快照）
- [ ] 首次启动需要配置什么，README 里说清楚（不能假设对方有 Ollama）

## 四、兼容性

- [ ] `dsh.compatibility` 声明了支持的 DSH 版本范围
- [ ] 列出依赖的内部约定，并说明"DSH 升级后需重新验证"
      （插槽键、遮蔽优先级规则、内置条目 `inject` 契约、事件流形状）
- [ ] 在**目标平台**上验证过（Web 宿主通过 ≠ 桌面端通过，注入语义不同）
- [ ] 至少在一个**干净环境**验证（不是开发机）

## 五、功能与体验

- [ ] 关键路径有自动化测试，且**反向验证过**每条断言能抓住它要防的 bug
- [ ] 性能在**有负载**时测过（空载和流式下的表现可能差 50 倍）
- [ ] 资源有上限（缓存条数、请求并发、定时器数量）
- [ ] 有全局开关，用户能一键关掉
- [ ] 出错时**静默降级**到原始行为，而不是显示错误或空白

## 六、发布配置

- [ ] GitHub 仓库 + **`dsh-plugin` topic**（插件市场按此 topic 发现）
- [ ] `package.json`：去掉 `"private"`、补 `repository` / `keywords` / `version`
- [ ] `LICENSE`
- [ ] `PROVENANCE.md`（参照 `dsh-whale-widget`，说明代码来源与第三方内容）
- [ ] `files` 白名单包含运行所需的一切（漏了会发布出跑不起来的包）
- [ ] README 中英双语
- [ ] 版本号 + CHANGELOG

## 七、已知限制要坦白

- [ ] 明确写出**覆盖范围**（哪些视图/场景没接管）
- [ ] 明确写出**质量依赖**（如翻译质量取决于所选模型）
- [ ] 明确写出**性能边界**（什么情况下会慢）
- [ ] 明确写出**未验证的部分**（我发布前必须补的：标准安装路径、重复渲染的定性）
